## Найдено в первых прогонах на реальных задачах

- [ ] **P5. Критику каждый раз отправляется полный план** (десятки килобайт промпта за обсуждение), хотя сессия у него
  сохраняется. Слать дифф к прошлой версии плана + полный текст только при первом ревью.
- [ ] **P6. Секреты в `.debate/`.** Логины и пароли, которые пользователь пишет агентам, лежат открытым
  текстом в `transcript.md`, `raw/*.prompt.md`, `state.json` и уходят обоим провайдерам. Как минимум
  предупреждать при вводе похожего на пароль; как вариант — маскировать в логах.
- [ ] **P7. Проверка входа перед запуском.** Первый прогон упал на «Not logged in» у Claude уже после хода
  Grok. Перед стартом делать быструю проверку авторизации обоих CLI.

- [ ] **Следить: в одном из прогонов автор принял все пункты критика, не отклонив ни одного.** Критика выглядела обоснованной,
  но если это повторится, это поддакивание в обратную сторону. Вариант: требовать от автора для каждого принятого
  пункта короткую проверку по коду («подтверждаю: файл:строка»). Сейчас он это делает сам.
- [ ] Подсказывать добавить `.debate/` в `.gitignore` целевого репозитория (сейчас — только совет при `run`).

## Найдено на этапе исполнения (длинная задача, смена ревьюера на OpenCode)

- [ ] **Вопрос ревьюера пользователю** («запускать ли тесты?») после ответа снова уходит ревьюеру, и тот повторяет то же
  ревью. Ответ должен уходить исполнителю как указание, а ревью — делаться после правок.
- [ ] Ревьюер получает полный дифф (~110 КБ) на каждом круге, даже в своей сессии. Слать дифф к прошлому кругу.

## Проверить на живых CLI (адаптеры qwen и opencode)

- [ ] Qwen Code: принимает ли `--allowed-tools run_shell_command(...)` и работает ли он вместе с `--approval-mode plan`
  (`debate probe qwen`, строки «разрешение по шаблону» и «только для чтения»). Как Qwen сообщает об отказе в правах —
  в документации не описано; сейчас ищем `permission_denials` в итоговом сообщении, как у Claude.
- [ ] OpenCode (частично проверено: `permission` с шаблонами bash работает, запрет записи работает). Используется классический `permission` (`edit`/`bash`/`webfetch`
  с шаблонами); в новой документации есть формат V2 (`permissions` массивом). Как в событиях `--format json` выглядит
  отказ инструмента — ищем `state.status = error` с текстом про запрет.

## Сделано

- [x] **Пересмотр плана с этапа исполнения.** В меню «Ревью не пройдено» — «вернуть план на обсуждение»: автор и критик
  получают отчёт исполнителя и последнее ревью, пересматривают план, после «го» исполнитель доводит уже внесённые
  изменения до новой версии в той же ветке. Раньше комментарий «покритикуйте план» уходил исполнителю.
- [x] `debate init`: находит установленные CLI, показывает версии, по согласию проверяет вход одним коротким запросом,
  предлагает роли (критик и ревьюер — по возможности другой агент, чем автор) и пишет `[roles]` в общий конфиг
  или в конфиг репозитория (`--here`), не трогая остальное. Подсказка про `init` при `run` без конфигурации.
- [x] Запасные агенты: `critic = ["grok", "opencode"]`. Лимит / нет входа / нет CLI → роль сама уходит следующему
  с вводной (задача, текущий план), исчерпавший лимит агент больше не вызывается в этом обсуждении; при других ошибках —
  пункт «передать роль запасному». Вводная теперь получает и агент, назначенный через `debate resume --role`.
- [x] Подсказки разрешений: разделители внутри кавычек не режут команду (был мусорный шаблон `Bash(class":*)`);
  голое `Write`/`Read`/`WebFetch` больше не предлагается — так критик и ревьюер однажды получили право писать файлы.
- [x] **Исполнение по умолчанию — прямо в репозитории, на ветке `debate/<имя>`**, а не в worktree: в worktree не было
  `node_modules`, `.env` и данных (ревьюер не смог собрать фронтенд), и папку приходилось убирать руками. Незакоммиченные
  изменения перед стартом — на выбор: stash / закоммитить самому / исполнять всё равно. При продолжении — проверка,
  что открыта ветка исполнения. Worktree — по `--worktree`. Итоговое окно подсказывает commit / merge / уборку.
- [x] Ревью не пройдено после всех кругов → меню: ещё круг правок / комментарий исполнителю / принять как есть / стоп
  (раньше молча «Исполнение завершено» с открытым blocker). `debate resume` открывает это меню и у таких уже
  завершённых обсуждений. Поля замечаний не по схеме (`file`/`text` у OpenCode) приводятся к `evidence`/`claim`.
- [x] Разрешения на склейки команд: `echo` больше не считается безобидным в подсказке; «ровно эти команды» — точный
  шаблон на каждую команду склейки; повторный отказ после разрешения не спрашивается по кругу.
- [x] Промпты агентам переведены на английский (точнее держат формат, меньше токенов); язык ответов — `[rules] language`.
- [x] **OpenCode работал не в том каталоге.** `debate probe opencode` показал: агент читал README.md из каталога, откуда
  запущен debate, а не из своего рабочего. OpenCode берёт каталог проекта из `$PWD`, а не из фактического cwd процесса.
  На этапе исполнения это означало бы правки в основном репозитории вместо worktree. Теперь всем агентам передаётся
  `PWD` их рабочего каталога; тестовые обёртки переписаны на Python (sh при старте исправлял `$PWD` и скрывал ошибку).
  Проверено на живом OpenCode: разбор событий, разрешение по шаблону и запрет записи работают.
- [x] Конфиги слоями: встроенные → `~/.config/debate/config.toml` → `<репо>/debate.toml` (совместимость) →
  `<репо>/.debate/config.toml` → `--config` → флаги. `allow_debate`/`allow_exec` дописываются, остальные списки заменяются.
  Свои агенты наследуют вид с учётом переопределений. `debate config [--all]` — итог и источник каждого значения.
- [x] `debate resume --role РОЛЬ=АГЕНТ`: отдать роль другому агенту посреди обсуждения (например, у Grok кончился лимит).
  У нового агента новая сессия; смена пишется в transcript и сохраняется в state.json.
- [x] Прерывания без трейсбеков: `q` в любом меню = остановить/выйти; повторный Ctrl+C или Ctrl+D в меню — аккуратная
  остановка с сохранением; русская раскладка (й/к/т/ы → q/r/n/s) и похожие буквы (кириллическая «о»); в меню разрешений
  есть «s — остановить»; на верхнем уровне вместо трейсбека — «Остановлено, продолжить: debate resume».
- [x] Найдено на этапе исполнения: у исполнителя не было даже `grep`, подсказка «уже разрешено»
  была ложной (смешивались этапы), а `Write`/`Read` вне рабочего каталога предлагались целиком. Теперь у исполнителя
  те же команды чтения; разрешения хранятся раздельно для обсуждения и для исполнения; для файлов вне каталога
  предлагается только их папка (`Write(//tmp/x/**)`), для WebFetch — только домен.
- [x] Адаптеры **Qwen Code** и **OpenCode**; модель у каждого агента (`model`), свои имена агентов (`[agents.deepseek] kind = "opencode"`),
  `debate run --role РОЛЬ=АГЕНТ --model АГЕНТ=МОДЕЛЬ`, `debate resume --model`, `debate models <агент>`;
  `debate probe` по умолчанию проверяет только назначенных агентов.
- [x] Открытые minor-замечания после консенсуса: исполнитель учитывает каждое или объясняет отказ, ревьюер это проверяет.
- [x] **P3.** Grok получает тот же read-only список, что Claude (`--allow Bash(...)`); probe подтвердил, что `--allow`
